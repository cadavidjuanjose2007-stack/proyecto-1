El árbol que guarda la integral

Árboles de segmentos y sumas de Riemann: por qué cada nodo es un área parcial

Alexander Narváez · material de apoyo

1. De dónde venimos

Tenemos una imagen binaria y, de cada columna, sacamos una altura. El resultado es un arreglo de enteros:

M = [ f(0), f(1), f(2), … , f(n−1) ]

Como cada columna mide un píxel de ancho, el área bajo la curva es simplemente la suma de ese arreglo:

A = Σ f(xi) · Δx   con Δx = 1

Sumar un arreglo cuesta O(n) y no hay nada que mejorar si solo queremos el total una vez. La pregunta interesante aparece cuando queremos otra cosa: el área de un tramo cualquiera, muchas veces, o poder modificar la curva y volver a preguntar.

2. La propiedad que lo permite todo

La integral es aditiva sobre intervalos. Si partes el dominio en dos, las dos partes suman el total:

∫ac f = ∫ab f + ∫bc f

Esa igualdad, leída como estructura de datos en vez de como teorema, es un árbol binario. Un nodo guarda el área de su intervalo; sus dos hijos guardan las áreas de las mitades. No hay más idea que esa en todo el documento.

Cómo se construye, paso a paso

Antes de mirar el árbol terminado conviene verlo armarse. Sigue los pasos: primero la imagen con sus columnas, después el vector de alturas, y por último el árbol levantándose desde las hojas.

paso 0 de 6

Fíjate en la lectura doble de cada nodo: como dato es una suma almacenada; como matemática es una integral definida sobre un subintervalo. El árbol no calcula la integral — la guarda descompuesta.

3. Cada nivel es una suma de Riemann distinta

Aquí está lo que a mí me parece lo más bonito de la estructura. Si en cada nodo de un nivel usas la altura promedio de su intervalo, obtienes una aproximación rectangular de la curva. Y cada nivel del árbol es una aproximación con distinto Δx.

1 → 2 rectángulos, Δx = 4

Un detalle que conviene decir en voz alta: el área total es la misma en todos los niveles. Lo que mejora al descender no es el valor de la integral, sino la fidelidad del perfil. El árbol conserva la suma exacta en cada nivel y va revelando la forma poco a poco.

4. Consulta de un tramo: por qué O(log n)

La pregunta que el arreglo plano contesta mal: ¿cuánta área hay entre x = 2 y x = 7? Con el arreglo hay que recorrer las columnas una por una. Con el árbol, basta con encontrar un puñado de nodos cuyos intervalos, juntos, cubran exactamente el tramo pedido.

2 7
Área del tramo — Nodos usados — Columnas que habría sumado el arreglo —

La garantía es geométrica, no empírica: en cada nivel del árbol, a lo sumo dos nodos quedan “a medias” en el borde del intervalo pedido. Como hay log₂(n) niveles, el total de nodos sumados está acotado por 2·log₂(n). Con n = 1000 columnas, cualquier tramo se responde con unos veinte nodos en vez de mil sumas.

5. Modificar una columna

Si cambia f(x) en una sola posición, solo dejan de ser válidos los nodos que contienen esa posición — y esos forman exactamente un camino desde la hoja hasta la raíz.

5 → se recalculan 4 nodos de 15

6. Poda: de aquí sale la cuadratura adaptativa

Hasta ahora el árbol se construye completo. Pero hay una pregunta natural: ¿vale la pena descender por todas las ramas?

Si dentro de un nodo la curva es casi plana, sus dos hijos no aportan información nueva: el rectángulo del padre ya describe bien esa zona. Si en cambio la curva cambia mucho dentro del nodo, descender sí paga.

criterio de poda: | izquierda − derecha | < ε  →  no descender

Un árbol construido con esa regla es profundo donde la curva se mueve y superficial donde es plana. Eso es exactamente lo que hacen los métodos de cuadratura adaptativa reales — los que están dentro de scipy.integrate.quad o de las rutinas QUADPACK. Concentran el esfuerzo donde el integrando lo exige.

Aquí el árbol deja de ser una estructura de almacenamiento y se vuelve una estrategia de refinamiento. Es el mismo objeto respondiendo otra pregunta.

7. El código

Haskell — el árbol como tipo algebraico

En un lenguaje funcional el árbol de segmentos no es una técnica: es la forma natural del tipo. La suma es un fold sobre esa forma.

-- cada nodo guarda la suma de su intervalo
data Seg = Hoja Int
         | Nodo Int Seg Seg

suma :: Seg -> Int
suma (Hoja v)     = v
suma (Nodo s _ _) = s

-- construccion: O(n)
construir :: [Int] -> Seg
construir [x] = Hoja x
construir xs  = Nodo (suma i + suma d) i d
  where (a, b) = splitAt (length xs `div` 2) xs
        i      = construir a
        d      = construir b

-- consulta del area en [l, r): O(log n)
consulta :: Seg -> (Int, Int) -> (Int, Int) -> Int
consulta t (a, b) (l, r)
  | r <= a || b <= l = 0          -- disjunto
  | l <= a && b <= r = suma t      -- contenido
  | otherwise        = case t of
      Hoja v     -> v
      Nodo _ i d -> let m = (a + b) `div` 2
                    in  consulta i (a, m) (l, r)
                      + consulta d (m, b) (l, r)

-- el area total es la raiz
area :: [Int] -> Int
area = suma . construir

C++ — el árbol como arreglo

La versión imperativa clásica no usa punteros: mete el árbol dentro de un arreglo, donde el hijo izquierdo del nodo k es 2k y el derecho 2k+1.

struct SegTree {
    int n;
    vector<long long> t;

    SegTree(const vector<int>& M) : n(M.size()), t(2 * M.size()) {
        for (int i = 0; i < n; i++) t[n + i] = M[i];      // hojas
        for (int k = n - 1; k > 0; k--) t[k] = t[2*k] + t[2*k+1];
    }

    // area en [l, r)
    long long consulta(int l, int r) {
        long long s = 0;
        for (l += n, r += n; l < r; l /= 2, r /= 2) {
            if (l & 1) s += t[l++];
            if (r & 1) s += t[--r];
        }
        return s;
    }

    // cambiar f(x) y reparar el camino hasta la raiz
    void actualizar(int x, int valor) {
        for (t[x += n] = valor; x > 1; x /= 2)
            t[x/2] = t[x] + t[x^1];
    }
};

Prolog — el árbol como relación

En lógica no se construye el árbol: se declara qué relación debe cumplirse entre un intervalo y su área.

% area(+M, +Desde, +Hasta, -Area)
area(_, L, L, 0) :- !.
area(M, L, R, Area) :-
    R is L + 1, !,
    nth0(L, M, Area).
area(M, L, R, Area) :-
    Medio is (L + R) // 2,
    area(M, L, Medio, Izq),
    area(M, Medio, R, Der),
    Area is Izq + Der.

Es la misma aditividad del intervalo, escrita como tres cláusulas: el caso vacío, la hoja y la partición.

No lo uses si solo quieres el área total una vez: construir el árbol cuesta O(n), igual que sumar el arreglo, y encima gastas el doble de memoria. La estructura se paga sola cuando hay muchas consultas de tramo o actualizaciones intercaladas.

Si hay muchas consultas pero nunca se modifica nada, hay algo más simple que gana: la suma de prefijos S[k] = f(0)+…+f(k−1), que responde cualquier tramo en O(1) con una resta, S[r] − S[l]. El árbol vale la pena justamente cuando además hay que actualizar — ahí la suma de prefijos se cae, porque cambiar una columna obliga a recalcular todo el resto.

La suma de prefijos, dicho sea de paso, es la función de área acumulada A(x). Es la misma A(x) de la que sale A′(x) = f(x). El teorema fundamental del cálculo, en versión discreta, es una tabla de sumas parciales.

9. Preguntas para pensar

  • Si en cada nodo, además de la suma, guardas el máximo de su intervalo — ¿qué preguntas nuevas puedes responder en O(log n)?
  • El árbol supone n potencia de 2 para quedar perfecto. ¿Qué pasa con n = 567, el ancho real de la imagen? ¿Rellenar con ceros, o permitir intervalos desiguales?
  • La suma de un nodo es exacta. Su rectángulo no. ¿Cómo medirías, dentro de un nodo, cuánta forma se está perdiendo — y usarías eso como criterio de poda?
  • Si la operación no fuera sumar sino multiplicar, ¿seguiría funcionando la estructura? ¿Qué necesita cumplir la operación para que un árbol de segmentos sea válido?
